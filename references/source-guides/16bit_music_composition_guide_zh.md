## 第 1 章：16bit 音乐不是一种统一音色

### 1.1 先区分三个不同概念

“16bit 音乐”可能指数字音频的 16 位 PCM，也可能指 16 位主机时代的游戏音乐，还可能指今天模仿那一时代声音的作品。

| 说法 | 实际含义 | 它不能单独告诉你的事 |
| --- | --- | --- |
| 16 位 PCM | 振幅量化精度 | 音乐是否像 SNES、是否使用 FM |
| 16 位主机音乐 | 某一历史时期与硬件环境中的作品 | 每台机器有何种音色与限制 |
| 16bit 风格 | 对那个时代声音、编曲与表现方式的再创作 | 是否能在真实主机运行 |

把 WAV 保存为 16 位 PCM，不会自动变成《超级任天堂》或《世嘉 Mega Drive》的声音。现代钢琴录音也可以是 16 位 PCM。

### 1.2 两条代表性路线

本文选择两个最值得分别练习的声音系统，而不把整个时代混成一种“复古音源”。

| 维度 | SNES／SFC | Mega Drive／Genesis |
| --- | --- | --- |
| 核心声音路线 | BRR 压缩采样播放 | 四运算器 FM，加 PSG 与 DAC 采样播放 |
| 基础资源 | 八路声音，共用音频 RAM | 六路 FM；第六路可改作 DAC；另有三路方波和一路噪声 |
| 创作时常见关注点 | 采样选择、循环、音色统一、声部预算与回声 | 频率比例、调制包络、律动、FM 与鼓的搭配 |
| 容易做差的地方 | 全部柔软化，变糊；声部和内存超预算 | 所有声音都很亮很硬；FM 与采样分工不清 |

这些基础架构分别见 SNES 开发资料及 Furnace 对 YM2612、Sega PSG 的说明。[S1][S5][S7]

SNES 并不只适合管弦、温暖或氛围；Mega Drive 也不只适合金属、电子或快速战斗。上述区分是学习入口，不是风格边界。

### 1.3 三种创作目标要提前选

1. **现代复古配乐**：最终播放 WAV／OGG，可以自由增加音轨、效果和声部。
2. **遵守指定主机的作品**：模拟主要限制，音色和编曲在该硬件能力内，但仍需验证工具行为。
3. **真实主机可运行作品**：还要通过目标音乐驱动、内存、指令、CPU 与游戏音效占用的验证。

插件听起来像主机，不等于工程可以直接导出到主机。本文的完整练习采用“按硬件资源思考、先在现代工具中完成”的路线；真实运行是独立的下一层验证。

## 第 2 章：从 8bit 到 16bit，创作难点变在哪里

### 2.1 更丰富的音色，带来更多需要协调的差异

一个方波、一个三角波与噪声，容易建立清楚的身份。换成短采样或 FM，你可能同时拥有笛子、弦乐、电钢琴、贝斯、铜管与鼓。

新问题随之出现：它们的起音速度、响度、频谱和空间感可能彼此不合。单独听都不错，合起来却像不同歌曲的素材拼接。

因此，16bit 风格的核心进步不是“再叠几件乐器”，而是让不同声音像同一个音乐世界里的人物。

### 2.2 三个特别重要的判断

**声音有没有明确职责？** 主旋律讲故事，低音建立重心，和声支撑关系，鼓组织动作。角色可以交换，但不能一直含混。

**音色是否具有共同的尺度？** 一条特别清晰、特别宽的现代立体声弦乐，旁边放一个短而窄的旧式采样，常会显得不在一个空间。

**每个音符有没有适合乐器的说法？** 同一串音，用拨奏音色可以很轻巧，用慢起音弦乐逐音重触发可能几乎听不到旋律。配器需要连同音长和节奏一起改。

### 2.3 判断质量的五个问题

- 去掉装饰声部，主题还成立吗？
- 从第十秒跳到第二十秒，能感到发展吗？
- 闭眼听，能否指出主要焦点？
- 连听五轮，哪一个声音最先使人疲劳？
- 放进游戏后，情绪与玩家行为是否一致？

不要只问“这像不像旧游戏”，还要问“如果第一次听到它，我为什么愿意继续听”。

## 第 3 章：先写清场景与声音边界

### 3.1 一张足够实用的制作卡

```text
场景：傍晚，玩家来到仍在运转的小港口。
行为：散步、交谈、观察，偶尔出现支线事件。
情绪：平静、好奇，略带期待；不要过度悲伤。
主题身份：两小节能辨认，适合后续改编。
音色路线：先做 SNES 采样版，再做 MD FM 版。
长度：16 小节，可循环。
最大风险：弦乐太糊、旋律过尖、鼓过于强势。
```

这会帮助你拒绝很多“单独好听但不适合这里”的音色。

### 3.2 先选一个声音主角

SNES 版可以让短笛感采样承担主题，弦乐只提供和声。MD 版可以让柔和 FM 主音承担主题，电钢琴短句提供回答。

先完成“主角加低音”的八小节。确认音乐成立之后，再逐步增加环境与细节。

### 3.3 每次只比较一个变化

同一段旋律，用短起音与慢起音各导出一版；保持其他内容相同。比较是否更清楚、更适合动作，而不是同时更换调性、速度、鼓和音色。

熟悉开发的人可以把它理解为控制变量：先知道哪个变化解决了哪个听感问题，再把有效变化组合起来。

## 第 4 章：SNES——用很短的采样建立乐器感

### 4.1 采样不是一整段表演

采样可以是一小段笛子、弦乐、敲击，甚至只有几个波形周期。系统以不同速率播放它，就能得到不同音高；再加包络与循环，形成可以演奏的乐器。

SNES 的八路声音播放 BRR 数据，音频 RAM 总计 64 KiB，并且还要容纳程序、数据和回声缓冲，不是全给采样用。标准输出为约 32 kHz 立体声；这不要求每个采样素材都以 32 kHz 录入。[S1]

想象你在做一个微型资源包：素材库很小，但同一素材能被多次调用、变调、裁剪和组织。

### 4.2 好采样首先要有可用的音头

初学常把注意力全放在持续部分是否“像弦乐”。但乐器识别和节奏清晰度，经常先来自声音开始的几十毫秒。

一个很实用的分配原则：保留能说明“这是什么乐器”的音头，压缩较稳定的持续段，删掉不必要的原始尾音，再由包络与共享空间建立结束感。

这不是要求所有声音都短。重要的打击尾音、自然颤动或呼吸本身有时就是风格核心，应通过试听决定。

### 4.3 一个可执行的素材处理顺序

1. 先听原素材，选出真正有用的音区和演奏方式。
2. 去掉无意义的起始静音，保留需要的起音。
3. 检查直流偏移、过载与突兀截断。
4. 找稳定持续段，建立循环。
5. 校准素材实际基音和工具的根音映射。
6. 用几个不同音区试听，而不是只听原音。
7. 转换为 BRR，再听一遍实际转换结果。
8. 放入编曲，判断是否还需要进一步裁剪或降低采样率。

先裁剪再评估音质，通常比对整段长录音盲目降采样更有效。

### 4.4 BRR 的容量要算，但不要只盯着容量

BRR 每个块以 9 字节存储 16 个解码采样点。[S2]

粗略容量公式：

```text
BRR 字节数 ≈ 9 × ceil(采样点数 / 16)
采样点数 ≈ 素材采样率 × 素材时长
```

例如一个单声道素材，以 16,000 Hz 保留 0.25 秒，共 4,000 点，BRR 主体约 2,250 字节。目录、对齐和其他数据另计。10 个同等大小素材约 22,500 字节，已经是值得管理的资源。

**这一公式只帮助估算存储，不能保证声音质量。** 预测滤波、量化、插值和变调都会影响最终听感；BRR 也不能简单理解成把 WAV 的每个样本直接截成 4 位。

### 4.5 降采样要分乐器，不要整库一刀切

低音持续段与镲的高频信息需求不同。一个采样率对低音够用，对镲可能已经损失太多细节。

每次降低后，先比较音头、音准和噪声，不只比较文件大小。降采样前应有合适的低通抗混叠处理；不要直接每隔几个点取一个数。

严格风格并不要求故意把所有素材做脏。资源预算内，保留真正有音乐价值的细节。

## 第 5 章：SNES——音符包络、循环点与演奏

### 5.1 循环点应该“接得上”，也应该“听得过去”

有持续段的乐器可以先播放音头，再循环稳定片段。循环需要同时考虑：边界振幅、变化趋势、周期关系和噪声纹理。

两个端点都接近零，不一定就无缝；若一个上升、另一个下降，拼接仍可能产生明显折角。对于复杂声音，过短的循环还可能变成不自然的蜂鸣。

BRR 以 16 点为块，循环地址需要适应块边界；编辑器通常要求相应循环位置按 16 点对齐。要按工具的“末点包含／不包含”约定设置，并检查编码后的结果。[S2][S3]

**不要先做一个任意循环，再随意四舍五入到 16 的倍数。** 应在满足对齐条件的候选点里找听感合适的接缝，必要时重采样或重新制作素材。

### 5.2 循环保留的是稳定段，不是整个音符

若把完整音头放进短循环，每轮都会再次“吹一下”或“敲一下”。某些音效需要它，普通持续笛音往往不需要。

一个常用结构：音头只播一次，持续段循环，音符停止时由包络或驱动安排结束。自然尾音若必须保留，可能需要更复杂的采样和驱动设计。

### 5.3 根音错了，调式会替你背锅

有些作品听起来“不和谐”，不是和弦错，而是某个素材根音标记错了。

拿一个持续音与参考音比较，在基准音及上下八度分别试听。自然乐器的音头可能带瞬时音高变化，校准时应结合稳定部分与最终听感。

一个乐器只用一个采样覆盖很大音域，容易低处拖沓、高处过薄。可以增加不同音区的素材，但要重新支付内存与切换成本。

### 5.4 包络参数不要照搬现代合成器的名字

通用合成器常用 A、D、S、R 描述起音、衰减、持续和释放。SNES 硬件的 ADSR／GAIN 行为与现代插件的自由毫秒曲线并不完全相同；工具还能通过驱动操作实现额外释放方式。

例如 Furnace 的 SNES 乐器编辑器区分 Sustain／Release 模式，并提供 D2、R 等控制。不能看到一个 R 就假设它等于芯片里独立可调的现代 Release 旋钮。[S4]

学习时先用听感目标：

| 角色 | 目标 | 常见需要避免的问题 |
| --- | --- | --- |
| 笛感主旋律 | 起音清楚，持续略有变化，句尾自然 | 音头太慢，短音全部被吞 |
| 拨奏 | 明确瞬态，较快衰减 | 每个音都像点击，无音高主体 |
| 弦乐和声 | 缓一点进入，避免每拍重新“吸气” | 太长尾音跨和弦，发糊 |
| 低音 | 重心明确，音长与鼓配合 | 音太低，持续太长 |

把目标映射到所用工具，再试听实际播放。别把跨软件包络数字当成通用配方。

### 5.5 乐器演奏方式要写进谱面

对比同一串四个音：

- 笛子可以在句中连贯，在句尾留呼吸。
- 弦乐可以减少不必要重触发，让几个音形成一句。
- 拨奏即使音符格子很长，声音也可能迅速衰减。
- 鼓不应因为谱面事件结束就总被截掉关键尾巴。

短样本的表现力，常来自“你如何播放它”，不只是原始采样有多真实。

## 第 6 章：SNES——八声部与共享回声的取舍

### 6.1 八声部不等于八件乐器随便演奏

一个三音和弦同时占三路。再叠一层相同三音弦乐，就可能占六路；若两边都是需要分别播放的立体声素材，成本可能进一步增加。

每个 DSP Voice 可以将自身输出分配到左右声道，这不等于播放一对独立的立体声录音只需一路。

计算资源时数“同时进行的实际发声”，而不是 MIDI 轨道数或乐器名称数。

### 6.2 先做一个声部分配表

| Voice | 工作 | 取舍 |
| --- | --- | --- |
| 1 | 主旋律 | 短时间保持焦点 |
| 2 | 低音 | 单音线条 |
| 3—4 | 两个和声内声 | 与低音共同提示和弦 |
| 5 | 分解和弦或回答 | 两种角色错时使用 |
| 6 | 底鼓与军鼓轮替 | 同时需要时必须改安排 |
| 7 | 镲 | 可以与 Voice 6 同时发声 |
| 8 | 预留音效或少量重点音 | 不必一直用满 |

包络尾音还在响，就仍可能占用 Voice。下一音抢占旧音时，检查是否产生突兀切断。

### 6.3 Echo 是共享处理，不是每轨一套现代混响

SNES 有共同的回声路径，可选择哪些 Voice 送入；延迟、反馈和 FIR 等核心设置是共享的。每轨独立加载不同大厅混响，属于现代扩展。[S1][S10]

原生 Echo 不额外消耗一个普通 Voice，但消耗音频 RAM。对正的 EDL 值，常用估算是每步约 16 ms、2 KiB；如 EDL=4 约 64 ms、8 KiB。EDL=0 的特殊行为不适用这个简单推算。[S1]

### 6.4 先决定什么需要湿，什么需要干

试着先让旋律与少量和声进入 Echo，低音与底鼓保持更干。听者会同时感到空间和节奏轮廓。

若所有声部都回声很重，会出现三种常见后果：低音不清楚；鼓的重拍被反射拖长；上一个和弦的尾巴与新和弦打架。

建议调节顺序：先低反馈、低回声返回；加到刚能感到空间；再检查停顿与换和弦。FIR、负反馈与相位反转能创造特殊质感，但初稿不要靠它们强行“做宽”。

### 6.5 空间要与内存一起取舍

如果回声缓冲已占太多 RAM，先考虑更短延迟、更精简采样、减少重复素材或采用更稀疏的配器。不要默认“加大混响”是免费的。

现代插件可以提供便利或扩展能力。以原生为目标时，必须另看整个工程的预算，而不只看某个乐器窗口里是否显示八路声音。

## 第 7 章：Mega Drive——把 FM 合成听懂

### 7.1 一个正弦波，为什么能变成电钢琴与铜管

可以先把一个运算器想成“一个带音高和包络的正弦振荡器”。直接送到输出的运算器常称为载波；影响另一个运算器的叫调制器。

教学上可用一个简化的两运算器模型：

```text
y(t) = A(t) × sin(2π fc t + I(t) × sin(2π fm t))
```

`fc` 是载波频率，`fm` 是调制器频率，`A(t)` 控制整体振幅，`I(t)` 控制调制深度。这个写法是相位调制形式，有助于理解 Yamaha 数字 FM 的听感，不能把它直接当作完整 YM2612 仿真算法。

你真正需要记住的是：**调制器不仅决定声音有多亮，还可以决定亮度怎样随时间变化。**

### 7.2 四个关键变量

| 变量 | 在控制什么 | 初学时的听法 |
| --- | --- | --- |
| Algorithm | 四个运算器如何连接 | 是串联得复杂，还是分成几个较简单部分 |
| Frequency Ratio／MULT | 运算器之间的频率关系 | 比例改变后，声音是否更有谐波感或金属感 |
| Modulator Level | 调制程度 | 音头是否更亮、是否开始发硬或失去清楚音高 |
| 各运算器包络 | 音量与音色怎样发展 | 是否音头亮、持续柔和；是否尾部一直嘶响 |

YM2612 是六通道、每通道四运算器的系统。四运算器通常共同建立一个音色，不是四条随便独立弹奏的普通 MIDI 音轨。特殊通道模式另有条件，本教程初稿不用。[S5][S6]

### 7.3 电钢琴感：亮的部分先走，温暖的部分留下

先建立一个调制器到一个载波的简单连接。载波保持较长衰减，调制器衰减更快：音头有亮度与敲击感，随后变柔和。

若只缩短载波音量而保持调制器很强，声音可能只是越来越小，仍然一直很硬。把“响度变化”和“谐波变化”分别听，是理解 FM 的关键。

### 7.4 一套能实际输入的基础 FM 练习参数

在 YM2612／OPN 编辑器中选择具有“两组独立的两运算器串联，再相加”拓扑的算法。标准 OPN 编号通常为 Algorithm 4；**以连接图为准，不按界面中的排列位置猜运算器编号**。

先只使用其中一组，另一组的输出载波设为静音。按图找到有效的调制器 M 和载波 C：

| 参数 | M：调制器 | C：载波 |
| --- | --- | --- |
| MULT | 1 | 1 |
| TL | 42 | 8 |
| AR | 31 | 31 |
| DR | 20 | 12 |
| SL | 10 | 6 |
| D2R／SR | 8 | 4 |
| RR | 9 | 9 |
| DT | 中性 | 中性 |
| AM | 关闭 | 关闭 |

全局 Feedback=0，LFO 关闭。未用的输出载波 TL=127，其分支不要再路由到有效载波。以上是标准 OPN 参数含义下的练习起点，不是跨合成器通用预设，也未经过听感调优。

注意参数方向：原始 OPN 的 TL 越大，衰减越多；AR、DR、RR 等速率参数通常越大变化越快。现代界面有时会把它们翻译成更直觉的旋钮，不能机械照抄。[S6]

先以中等音区弹短句，降低总输出，比较三个版本：

1. M 的 TL=52：调制更弱，通常更柔和。
2. M 的 TL=32：调制更强，比较音头是否更硬。
3. 恢复 TL=42，把 M 的 MULT 从 1 改为 2：比较谐波与身份的变化。

C 的 TL 先不变，避免把音色变化和整体响度变化混在一起。另一分支之后可以加入较弱的高频成分，但不要为了“用满四运算器”而强行添加。

### 7.5 一个好的 FM 低音不是最凶的低音

在鼓组旁边听它：基音是否可靠，音头是否帮助节拍，尾部是否留给下一拍。调制太深、反馈太强，低音可能独奏很酷，合奏只剩中高频摩擦。

先让载波提供稳定重心，再用较短的调制器包络制造轮廓。最低音区试完，还要听高八度；同一音色跨音区可能性格大变。

### 7.6 不是每一个 MIDI 力度都该只改变音量

现代 FM 工具可以把力度映射到载波、调制器或两者。只改载波，主要影响响度；改调制器，会同时改变明亮与硬度。多载波算法还需要检查各分支的平衡。

目标硬件和音乐驱动未必具有与现代插件相同的力度映射。先定义希望听到的差异，再验证工具与驱动如何实现。

## 第 8 章：Mega Drive——FM、PSG 与采样的分工

### 8.1 用 DAC 需要让出什么

YM2612 第六路进入 DAC 采样模式时，不能同时作为普通 FM 第六通道工作。常见基础预算因此是五路 FM 加一路 DAC，再加 PSG。[S5]

某些驱动通过软件混音，让多个采样合成为一个 DAC 数据流。那是软件能力与 CPU、带宽和音质的取舍，不是芯片突然有多个原生 PCM 通道。不要未经确认，就同时叠底鼓、军鼓、拍手和长人声。

### 8.2 一张可靠的初学角色表

| 资源 | 建议角色 |
| --- | --- |
| FM 1 | 主旋律 |
| FM 2 | 低音 |
| FM 3—4 | 两个和声内声 |
| FM 5 | 电钢琴回答、短琶音，或空置 |
| 第六路 DAC | 短鼓采样轮替 |
| PSG Tone 1 | 轻短点缀，可省略 |
| PSG Tone 2—3 | 预留，不强行填满 |
| PSG Noise | 镲或高频节奏轮廓 |

PSG 提供三路方波和一路噪声；某些噪声频率模式依赖第三路方波的频率，因此两者参数可能互相影响。初学先用固定噪声设置，避免把第三路当成完全无关的自由资源。[S7]

### 8.3 最重要的声音，交给最适合的生成方式

FM 负责可变化的音高与谐波，短采样提供具有识别度的敲击，PSG 提供清楚而轻巧的轮廓。你不需要证明“所有鼓都能用 FM 合成”，只需让整体好听。

反过来，采样并非必需。FM 与噪声也能构造有个性的打击。选择它们是为了风格与资源，而不是因为某条路线天然更高级。

### 8.4 立体声不要默认无限精细

标准 YM2612 通道的原生输出选择主要是左、右或左右同时，不是现代 DAW 任意连续的声像旋钮。Mega Drive 的 PSG 基础输出也不能直接当成 Game Gear 那套原生立体声开关来使用。[S8][S7]

现代作品可以后期细调声像；若声称按主机限制制作，就应把这些扩展单独注明。

## 第 9 章：旋律与和声——丰富，但不失去主题

### 9.1 先让节奏有身份

用一个音敲出两小节，形成可记的短长关系，再放入音高。主题如果只能靠特殊音色辨认，改编时会比较脆弱。

两小节之后，保留部分节奏，改变句尾或落点。听者一边认出它，一边发现新的方向。

### 9.2 音色丰富之后，长音更要有意图

一个明显的非和弦音，如果用强烈铜管持续一整拍，会比轻拨奏经过时更突出。检查旋律长音与当前低音，不能只看是否“都在同一音阶”。

初稿让多数重拍和长音落在清楚关系上；再挑一两处有意留下紧张，并通过后续音说明去向。

### 9.3 七和弦、九和弦不是成熟的快捷方式

Dm7、Bbmaj7、Fadd9 等可以增加色彩，但每个额外声部都可能带来音区与清晰度问题。

先把三和弦写好，再增加一个色彩音，比较是否真的更贴合场景。低音已经弹根音，其他声部未必还要重复根音；旋律已经长时间给出九音，伴奏也不必再补一遍。

### 9.4 内声少走一点，作品会更连贯

例如 Dm 的 F、A，转到 Bb 的 F、Bb：一个内声保留 F，另一个从 A 走到 Bb。低音换根音，上方不需要整块跳跃。

这就是声部进行的一个直接用法：让每条线有连续性，而不只是每小节堆出正确和弦。

### 9.5 小调可以有方向，而不是一直阴暗

以 D 小调为例，常用材料包括 `D E F G A Bb C`。为了让 A 和弦更明确地指向 Dm，常使用 C# 形成 A 大三和弦。

这不是“随便在小调里升音”，而是局部和声功能的选择。写到 A 和弦时，检查旋律里的 C 与 C#；两者也能并存，但需要明确想要的冲突。

### 9.6 伴奏忙时，旋律可以慢下来

不要让主旋律、分解和弦、低音与鼓同时证明技巧。主旋律拉长时，伴奏可以流动；主旋律出现细碎上行时，伴奏可以保留共同音。

音色层次已经丰富，进一步增加音符密度通常不是唯一的发展方式。

## 第 10 章：低音与鼓——让音乐真正动起来

### 10.1 先只听这一对

将其他声部静音，检查底鼓和低音是否构成能理解的重心。低音每拍都移动而底鼓不断换重拍，初稿容易没有参照。

先用第一、第三拍底鼓，第二、第四拍军鼓，再加入简单低音。等身体能自然跟拍，再添加切分或提前进入。

### 10.2 给底鼓与低音分配不同长度

短底鼓配略长低音，可以形成稳定推进；长底鼓配短低音，可能形成另一种律动。但两者一直拖尾，低频容易变成一团。

先调整时长、起点和音区，再考虑现代后期的 EQ 或侧链压缩。严格主机路线不应默认每轨都有动态处理器。

### 10.3 切分需要一个参照点

把某个低音提前半拍，可以带来期待；如果所有声部都持续提前，听者可能失去“提前到哪里”的感觉。

试着让鼓保持清楚，低音改变；或低音稳定，镲改变。先做局部的节奏对比，再扩展。

### 10.4 Swing 不等于随机偏移

Swing 是有组织的不均匀细分；随机把每个音偏移几毫秒，不一定更自然。不同 Tracker 的 Groove、Tick 与显示 BPM 关系不同，应看当前模式。

严格帧或 Tick 驱动中，可实现的时间位置有分辨率限制。不要把 DAW 毫秒偏移直接当成目标驱动保证支持的指令。

### 10.5 过门只需要说“下一句来了”

先试最后半拍加两个短击，或在回归前空半拍。每小节都长过门，会让段落没有真正稳定下来的时间。

DAC 单流或单声部鼓轨下，过门还会抢掉其他鼓的尾部。设计谱面时就检查它，不要交给随机抢占。

## 第 11 章：配器与空间——大不等于满

### 11.1 先在干声里成立

关掉回声和混响，检查和声、重音、焦点。空间效果可以连接声音，但不能替你完成配器。

一个实用办法：以主旋律为参照，让和声先低到几乎感觉不到，再慢慢加回来。找到“足够支撑”而不是“每轨都能清楚独奏”的位置。

### 11.2 按角色听频谱

| 区域或特征 | 常见任务 | 常见冲突 |
| --- | --- | --- |
| 低频与低中频 | 重心、厚度 | 低音、底鼓、低弦同时持续 |
| 中频 | 旋律身份、和声关系 | 电钢琴、主音、弦乐挤在一起 |
| 高频与瞬态 | 清晰、动作与闪光 | FM 亮音头、镲、拨奏都很尖 |
| 持续尾部 | 连接与空间 | 回声把所有句子连成一条线 |

这不是要求每件乐器只占一个频段，而是帮助你发现谁在争抢同一种感受。

### 11.3 音色统一可以先统一“距离”

把一件原本很远、很湿的现代素材与一个近而干的短采样放在一起，容易出现空间断层。先减少各素材自带的房间尾音，再用一套共同空间关系组织。

不要靠把所有声音都低通来“统一年代感”。有选择地保留一个清楚音头，比整首变暗更容易让作品有层次。

### 11.4 同一音区同时有三件乐器，先问谁该退出

如果副旋律与主旋律在同一音区同样活跃，最有效的修改常是删掉一拍、让副旋律回答，或更换音区。EQ 应处理剩下的声音关系，而不是掩盖编曲里的争吵。

### 11.5 高潮来自前面留下的余地

可以先不用完整鼓组，后面加入；先限制旋律音域，后面抵达高点；先只有低音和两内声，回归时加入拨奏。音量不变也能有高潮。

一个短曲从第一秒就用满音域、声部、亮度与回声，后面通常只能继续加响，而这往往使人更快疲劳。

## 第 12 章：完整实战一——SNES 风格《暮色港湾》

这是一份可在支持相应音源的工具中手动重建的原创练习谱。先做干声，再加回声；先完成结构，再精修音色。目标是学会判断和取舍，不是复刻任何现有游戏的旋律。

### 12.1 工程与记谱约定

| 项目 | 设置 |
| --- | --- |
| 拍号 | 4/4 |
| 速度 | 约 120 BPM |
| 调性 | D 小调，A 大三和弦处使用 C# |
| 长度 | 16 小节，约 32 秒 |
| 主旋律 | 单声道笛感采样 |
| 和声 | 同一套短弦乐或柔和持续音 |
| 节奏 | 短低音、底鼓、军鼓、镲 |
| 声部 | 使用前七路，第八路空置 |

`C4` 表示中央 C。不同软件八度编号可能不同，以实际音高为准。`音名:时值` 中时值以四分音符拍为单位，`R` 是休止；每个旋律小节合计四拍。

实际发声可以比占用的节奏格短。初稿中低音每拍发声约 0.75 拍，拨奏每半拍发声约 0.25 拍，再用休止或停止命令明确结束。包络尾部是否继续占 Voice，要用实际工具确认。

### 12.2 Voice 1：完整主旋律

| 小节 | 和弦 | 音符与时值 | 功能 |
| --- | --- | --- | --- |
| 1 | Dm | F5:0.5, A5:0.5, C6:1, A5:1, F5:1 | 建立主题与小调色彩 |
| 2 | Bb | F5:0.5, A5:0.5, Bb5:1, D6:1, R:1 | 保留节奏，句尾抬高再停顿 |
| 3 | F | A5:0.5, G5:0.5, F5:1, E5:1, F5:1 | 回落并短暂形成色彩 |
| 4 | C | G5:1, E5:0.5, D5:0.5, C5:1, R:1 | 第一组乐句结束 |
| 5 | Dm | F5:0.5, A5:0.5, C6:1, A5:1, F5:1 | 确认主题身份 |
| 6 | Bb | D6:1, C6:0.5, Bb5:0.5, A5:1, F5:1 | 变化句尾，扩大范围 |
| 7 | Gm | G5:0.5, A5:0.5, Bb5:1, D6:1, C6:1 | 推动进入转折 |
| 8 | A | C#6:1, D6:0.5, C#6:0.5, A5:1, R:1 | 用 C# 建立回归期待 |
| 9 | Gm | Bb5:2, A5:1, G5:1 | 对比段，减少旋律事件 |
| 10 | C | G5:1, C6:1, E6:2 | 达到一个较长高点 |
| 11 | F | C6:1, A5:1, G5:1, F5:1 | 逐步回落 |
| 12 | A | E5:1, A5:1, C#6:1, R:1 | 给回答声部留位置 |
| 13 | Bb | D6:0.5, C6:0.5, Bb5:1, F5:1, D5:1 | 熟悉节奏回归 |
| 14 | C | E5:0.5, G5:0.5, C6:1, G5:1, E5:1 | 承接并指向主调 |
| 15 | Dm | F5:1, A5:1, D6:1, A5:1 | 局部稳定 |
| 16 | A | E5:1, C#5:1, A4:1, R:1 | 保留入口，引回第 1 小节 |

第 1 小节 Dm 上的 C 是七音色彩，第 2、6 小节 Bb 上的 A 带有大七度色彩。这些音是有意保留的，不是因为“都在 D 小调里”就无需判断。

第 10 小节 E6 若太尖，先换成 E5，或换一种较柔和的音头，而不是马上压低全曲高频。第 16 到第 1 小节的旋律跳进，也应在实际速度下试听；需要更顺时，可把第 16 小节第三拍 A4 改成 A5。

### 12.3 Voice 2：低音模板

按每小节和弦选择一行。每个音占一拍，实际发声先略短于一拍。

| 和弦 | 四拍低音 |
| --- | --- |
| Dm | D3, A3, D4, A3 |
| Bb | Bb2, F3, Bb3, F3 |
| F | F2, C3, F3, C3 |
| C | C3, G3, C4, G3 |
| Gm | G2, D3, G3, D3 |
| A | A2, E3, A3, E3 |

第 9—12 小节改成根音两拍、五度两拍，减少事件。第 16 小节只演奏前三拍，最后一拍留空。

若 F2、G2 在小扬声器上模糊，先把对应低音上移八度，检查与和声的距离，再决定最终方案。

### 12.4 Voice 3—4：两条和声内声

每小节开始时同时进入，保持到约第 4 拍中段，末尾留出一点空隙。实际停止与释放按工具实现检查，不在下一小节自动叠出额外 Voice。

| 和弦 | Voice 3 | Voice 4 |
| --- | --- | --- |
| Dm | F4 | A4 |
| Bb | F4 | Bb4 |
| F | F4 | A4 |
| C | E4 | G4 |
| Gm | D4 | Bb4 |
| A | E4 | C#5 |

这两条内声加低音已经提供三和弦关系。Dm 与 F 的上方内声可以相同，低音改变会改变听到的整体关系。

为形成层次：第 1—4 小节两内声较轻；第 5—8 小节略增强；第 9—12 小节保持柔和；第 13—15 小节恢复；第 16 小节仅持续三拍。

如果某处高内声与主旋律碰得太近，先减弱或短暂停止 Voice 4。不要为了表格“完整”而保留听起来争抢的音。

### 12.5 Voice 5：分解和弦与回答

完整分解模板如下，每个音占半拍，使用短拨奏。注意 A 是大三和弦，使用 C#。

| 和弦 | 八个八分音符 |
| --- | --- |
| Dm | D4, F4, A4, F4, D4, F4, A4, F4 |
| Bb | Bb3, D4, F4, D4, Bb3, D4, F4, D4 |
| F | F3, A3, C4, A3, F3, A3, C4, A3 |
| C | C4, E4, G4, E4, C4, E4, G4, E4 |
| Gm | G3, Bb3, D4, Bb3, G3, Bb3, D4, Bb3 |
| A | A3, C#4, E4, C#4, A3, C#4, E4, C#4 |

按以下时间表安排，而不是全曲铺满：

| 小节 | Voice 5 的实际内容 |
| --- | --- |
| 1、3 | 全休止 |
| 2 | 前三拍休止；第 4 拍 D5 半拍、F5 半拍 |
| 4 | 前三拍休止；第 4 拍 E5 半拍、G5 半拍 |
| 5—7 | 对应和弦完整八音模板 |
| 8 | 模板前六音占前三拍；第 4 拍改 E5 半拍、C#5 半拍 |
| 9—11 | 全休止 |
| 12 | 前三拍休止；第 4 拍 C#5 半拍、E5 半拍 |
| 13—15 | 对应和弦完整八音模板 |
| 16 | 全休止 |

这里的“回答”发生在主旋律休止时。拨奏与回答共用一路，没有额外复制轨道。

### 12.6 Voice 6—7：鼓组

准备短底鼓 K、军鼓 S、轻镲 h。Voice 6 在 K 和 S 之间轮替，Voice 7 单独演奏 h。

| 位置 | 1 | 1& | 2 | 2& | 3 | 3& | 4 | 4& |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Voice 6 | K | 空 | S | 空 | K | 空 | S | 空 |
| Voice 7 | h | h | h | h | h | h | h | h |

变化：

- 第 1—4 小节镲只在后半拍“&”进入，让开头更稀疏。
- 第 5—8、13—15 小节使用完整表格，后半拍镲较弱。
- 第 9—12 小节删掉 Voice 7，保留轻一些的 K 与 S。
- 第 16 小节 Voice 6 只有第 1、3 拍 K，第 2 拍 S；所有声部最后一拍留空。

用短鼓样本，确认 K 或 S 的尾部不会在下一次触发时被切得难听。单声部轮替的成本在尾音里同样存在。

### 12.7 Echo 与平衡

先不加 Echo，确认七路组合清楚，再将 Voice 1、3、4 送入共享 Echo。初始可试 EDL=4，低反馈与低返回，其余声部保持干一些。

这里不给一个假装跨工具通用的“反馈 20%”硬件寄存器值。不同界面可能显示百分比、整数或有符号值，先确认语义，再按听感小幅增加。

按这个顺序加轨：主旋律 → 低音 → 两内声 → 鼓 → Voice 5 → Echo。每加一组都问：它增加了什么？如果只增加拥挤，就删减或调整。

### 12.8 五项针对性修改

1. 笛音短音不清楚：缩短起音，或减少短音数量。
2. 和声发糊：先缩短 Voice 3—4 的音长，再减少 Echo。
3. 第 5 小节变吵：降低拨奏密度，先只保留每拍起点。
4. 第 10 小节高点刺耳：改音区或包络，不急着改旋律结构。
5. 循环每次像重新开场：检查第 16 小节空拍是否过于彻底，必要时保留轻的和声或回声延续。

最后一项说明：全声部最后一拍留空只是这个练习的初稿设计，不是循环创作必须遵守的规则。

## 第 13 章：完整实战二——改编为 Mega Drive 风格

### 13.1 保留主题，改变发声组织

先保留《暮色港湾》的 D 小调、16 小节和弦与完整旋律，速度仍用约 120 BPM，便于比较。完成后再试约 132 BPM，观察是否更有街景移动感；此时全曲约 29.1 秒。

如果同时换调、换旋律、换速度、换鼓，很难判断变化来自哪里。

### 13.2 资源分配

| 资源 | 内容 | 与 SNES 版的区别 |
| --- | --- | --- |
| FM 1 | 原主旋律，柔和持续主音 | 缩小过亮音头，长音后段浅颤音 |
| FM 2 | 新低音节奏 | 更短、更强调切分 |
| FM 3—4 | 原两条内声 | 由持续弦乐改为短电钢琴式重音 |
| FM 5 | 原 Voice 5 的回答 | 分解和弦先删掉，仅保留明确回答 |
| 第六路 DAC | K、S 轮替 | 不使用未确认的软件多采样混音 |
| PSG Noise | 轻镲 | 与 DAC 的重音分开 |
| PSG Tone 1—3 | 先空置 | 只在后续版本添加必要点缀 |

这套基础版本用五路 FM、一路 DAC 与一路 PSG Noise。不是因为资源还有剩余，就需要填满。

### 13.3 FM 1：让持续音会变化

从一个柔和主音预设开始，或以第 7 章的简单分支实验为基础，减轻过快衰减，让旋律能持续。主旋律音头应清楚，持续阶段不必一直保持最亮。

第 9—10 小节长音出现后，再逐渐加入浅颤音。短音先不加。不要把所有包络、Feedback、LFO 同时随机改动。

目标是让主题从笛子的“呼吸感”变成 FM 的“谐波动态”，而不是仅仅把笛子换成更响的电子音。

### 13.4 FM 2：新的八分低音模板

每格半拍。根音、五度与高八度根音取自第 12 章低音表，按以下关系生成：

| 位置 | 1 | 1& | 2 | 2& | 3 | 3& | 4 | 4& |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 内容 | 根音 | 休止 | 根音 | 五度 | 休止 | 高八度根音 | 五度 | 根音 |

例如 Dm 小节是：

```text
D3:0.5, R:0.5, D3:0.5, A3:0.5,
R:0.5, D4:0.5, A3:0.5, D3:0.5
```

其他和弦按表格替换。每个有声音的半拍先发声约四分之一拍，余下时间留空。第 9—12 小节退回根音两拍、五度两拍的较长低音；第 16 小节只用前三拍。

加了这条线后，鼓不要立刻同步增加切分。保留节拍参照，听它是否已经足够推动音乐。

### 13.5 FM 3—4：从铺底变成短和声

沿用原来的两内声音高，但只在第 2、4 拍同时进入，每次占半拍，使用较短的电钢琴式衰减。

第 9—12 小节只在第 1 拍进入，延长到约两拍，给对比段空间。第 16 小节改为第 2 拍一次，最后一拍保持空。

两条线仍分别占两路 FM。四运算器电钢琴音色不会自动把两音和弦缩成一个普通通道。

### 13.6 FM 5：只保留回答

保留第 2、4、8、12 小节最后一拍的两个回答音，其他位置先静音。使用与主旋律有区别的短音色，不加持续尾巴。

如果确实需要更闪亮的回归，可以在第 13—15 小节加入稀疏单音伴奏。但请另存版本，先比较“有”和“没有”哪一个主题更清楚。

### 13.7 DAC 与 PSG：避免不知不觉超出预算

DAC 使用原来 K、S 的第一、二、三、四拍轮替；PSG Noise 使用原镲位置。不要在同一时刻给 DAC 写两件鼓，除非已验证驱动的混音能力。

这条严格资源路线不附加现代立体声混响。需要“回声感”时，可让 FM 5 在选定空隙重复减弱的片段，并明确占用通道；这样它就不能同时做另一条回答。

现代风格版本当然可以增加 Delay，但应另存并注明这是后期扩展，不把它当作 YM2612 自带的回声。

### 13.8 如何比较两版

尽量匹配听感响度，先以相同速度播放。每次只回答一个问题：

- 主题身份是否保留？
- 哪版更像散步，哪版更像移动中的街景？
- SNES 版的空间是否牺牲了清晰度？
- MD 版的音头是否过硬，低音是否抢走焦点？
- 关掉最高频声部之后，哪版改善更明显？

比较的目标是理解声音语言，不是判定两台主机哪一台“更高级”。

## 第 14 章：段落发展与游戏主题变奏

### 14.1 先画能量地图，再加新材料

| 区间 | 主要任务 | 本练习的体现 |
| --- | --- | --- |
| 1—4 小节 | 让玩家认识主题 | 拨奏少，回答清楚 |
| 5—8 小节 | 增加流动并转折 | 伴奏增加，A 和弦推动 |
| 9—12 小节 | 对比与呼吸 | 旋律变长，鼓和伴奏减少 |
| 13—16 小节 | 熟悉材料回归并衔接 | 恢复部分密度，结尾留入口 |

这张表只是一个可练骨架。以后可以改变分句长度、增加引子或桥段，但仍要能说明每个段落的工作。

### 14.2 对比优先改一个维度

A 段短音多，B 段长音多；A 段旋律较高，B 段降低；A 段和声固定，B 段加快变化。一次先选一个，避免对比段像另一首音乐突然开始。

### 14.3 同一主题做三个游戏状态

**港口日常版**：保持轻节奏，音域适中，长时间播放不夺取注意。

**发现秘密版**：保留主题开头，减鼓、拉长落点，加入一点未解决关系；不要只把全曲放慢就结束。

**遭遇追逐版**：保留节奏身份，增强低音动作、缩短和声发声、提高能量，再试听速度变化。

状态变化时，不一定整首从头重播。现代引擎可以在小节边界切换同长度分轨，或切到结构兼容的变体。需要共同起点、节拍网格与和声位置。

### 14.4 原生路线下，变奏还要核算资源

新状态换一套采样库，可能需要载入时间；加一轨，可能没有 Voice；更密的指令，可能增加驱动负担。音乐设计与运行时设计需要共同完成。

先做两个可靠状态，比在纸面上写出十个无法切换的层次更有价值。

## 第 15 章：循环、混音与导出

### 15.1 技术无缝与音乐自然要分开检查

音乐方面：最后的和声、旋律、节奏能否引回开头？

技术方面：循环是否丢拍、增加静音、截断尾音，或继承错误状态？

最后四小节接最初四小节单独听，再连续听五轮。第一轮正常并不能证明第二轮正确。

### 15.2 入口状态要明确

音序格式会保留乐器、音量、滑音、包络、声像或 Echo 等状态。循环起点应设定必要值，尤其要检查上一轮的效果是否不该继续。

若刻意保留连续状态，也要记录下来，保证从中途开始播放或状态切换时仍可控。

### 15.3 回声尾巴不能随便截

现代音频交付可以连续渲染多轮，在稳定后截取中间一轮，让前一轮尾部自然进入下一轮。带随机调制的效果器未必逐样本重复，仍要在目标播放器验证。

原生音序还涉及回声 RAM 的初始化与保持。声音文件的“中间一轮”方法不能替代驱动层面的处理。

### 15.4 先解决编曲，再做后期

修改顺序建议：

1. 删除无效音符与重复角色。
2. 调音长、包络和音区。
3. 调声部相对音量。
4. 调共享空间与声像。
5. 现代路线再处理 EQ、压缩及响度。

若每条轨都在同一拍强调同一个中频区域，整体低通只会得到更暗的拥挤。

### 15.5 四种试听环境

- 小音量：主题是否仍然明确？
- 单声道：有没有因为反相或过宽处理造成缺失？
- 普通扬声器：低音是否完全消失，鼓是否过尖？
- 游戏内：加入 UI、脚步、战斗音效后，关键信息是否仍能听清？

SNES 的左右反相、现代立体声增强等处理，尤其需要单声道检查。扩大声场不应以核心旋律消失为代价。

### 15.6 输出应该按用途选择

| 文件或数据 | 用途 | 应验证的点 |
| --- | --- | --- |
| 原工程 | 继续编辑 | 工具版本、音源配置、素材依赖 |
| WAV／FLAC | 无损交付与归档 | 采样率、位深、声道、尾部、循环点 |
| OGG／其他压缩格式 | 游戏运行资源 | 编码与目标解码器的循环行为 |
| 分轨 | 动态音乐与后期 | 同起点、同长度、同采样率 |
| VGM | 支持芯片的寄存器日志播放 | 芯片支持、循环、时序及播放器行为 |
| SPC | SNES 音频状态与程序播放 | 目标导出工具／驱动、RAM 与播放状态 |
| ROM／驱动数据 | 真实主机或模拟器实装 | 指令支持、预算、游戏音效抢占 |

Furnace 官方导出文档区分音频、分芯片／分通道输出和 VGM 等路径。支持编辑某芯片不等于所有原生格式都能无条件导出；不要由“有 SNES 音源”推断“当前版本必定可一键导出 SPC”。[S11]

16bit 风格不要求最终文件必须是 16 位、32 kHz。现代项目可以按统一制作与引擎要求交付，风格主要来自音源行为和编曲；如果用 16 位 PCM 最终交付，位深转换与抖动按实际处理链安排，不要反复降位深、再升回去。

## 第 16 章：工具、代码工作流与实装边界

### 16.1 主线工具怎么选

| 目标 | 候选路线 | 建议 |
| --- | --- | --- |
| 免费、研究多芯片与严格声部 | Furnace | 先只选 SNES 或 Genesis 一个系统 |
| 在 DAW 里做 SNES 风格 | chipsynth SFC | 用自己的素材建立乐器，另核算整体资源 |
| 在 DAW 里研究 MD FM | chipsynth MD | 学习四运算器路由和动态，不只浏览预设 |
| 现代复古游戏配乐 | 常规 DAW 加采样器／FM 音源 | 自设资源约束，但保留交付自由 |
| 程序生成 | Python 或 JavaScript／TypeScript | 将乐谱数据与声音渲染分开 |
| 真实 SNES 游戏 | 选定 SDK 与音乐驱动的导入流程 | 先验证最短测试曲，再扩成长曲 |

Furnace 的官方资料列出 SNES 与 YM2612 支持；Plogue 提供 SFC、MD 产品及相应手册。插件的现代分层、效果与宿主能力，应与原生资源限制分别看待。[S3][S5][S9][S12]

不必为了第一首练习购买全部工具。先用一条能稳定输入、播放和导出的路线完成作品。

### 16.2 编程者最值得采用的数据分层

```text
乐谱层：拍点、音高、时长、力度、声部、段落
演奏层：连奏、断奏、颤音、包络、音色切换
声音层：采样、FM 参数、芯片模拟或插件
输出层：音频文件、日志或目标驱动数据
```

四层拆开，可以用同一旋律比较两种声音实现，也能单独检查节奏、复音与资源。不要把具体合成器的参数散落在每个音符生成函数里。

对脚本来说，最有价值的自动检查往往是：小节时值是否正确；同一路是否意外重叠；是否超出目标复音；和弦切换时是否残留上一个音；输出循环长度是否匹配。

### 16.3 Python 适合什么

适合生成 MIDI、样本、包络、变奏与批量渲染，也适合测容量、接缝、峰值与事件排布。附录 B 用标准库生成一个可校准的持续音素材。

但几行“正弦波加调制器”的 Python 代码不会自动拥有 YM2612 的完整包络、量化、时序与模拟输出特点。要做指定主机声音，应使用成熟仿真，或明确自己的渲染器只是近似。

### 16.4 浏览器技术适合什么

JavaScript／TypeScript 结合 Web Audio、采样器或相关音乐库，可以做交互创作与试听；也可以控制 FM 风格的动态结构。浏览器的普通 FM 合成器同样不能自动等同于某块真实芯片。

这条路线最适合快速比较音色、参数与乐句，在网页中做音乐实验。若目标是主机格式导出，应另选相应后端，而不是把实时网页音频直接叫作主机工程。

### 16.5 原生实装先做一个最小样本

先验证一小段包含长音、短音、采样鼓、音色切换与循环的测试曲，确认目标驱动支持，再扩展成完整作品。

同时记录驱动允许的事件、时间分辨率、采样格式、RAM 用量与音效优先级。音乐写完才发现某个效果无法表达，代价通常更高。

素材来源也应随工程记录。优先用自己制作或明确允许使用的素材；原游戏音色可作为学习观察对象，不默认当成可发布的素材包。

## 第 17 章：从作曲家访谈提炼可练习的方法

### 17.1 David Wise：短素材可以通过组织产生变化

David Wise 在原始访谈中谈到，在 SNES 的内存限制下受到 Korg Wavestation 的短波形与 Wave Sequencing 启发，并把相关思路用于《Aquatic Ambience》；后来又探索了不同滤波状态的波形组织。[S13]

可借鉴的不是“给所有音轨加很多水下混响”，而是持续音内部也可以有结构。下面是本文设计的练习，不是对原曲实现的逐条复原：

1. 用同一基音制作三种谐波不同的短持续素材。
2. 先分别听，校准音高和主观响度。
3. 在一个长音的后半段切换或渐变，观察听感是发展还是突变。
4. 现代工具可做交叉淡化；原生驱动应另验证同 Voice 换素材是否支持、是否产生点击。若交叉淡化需要两 Voice，就把成本计入预算。

你也可以只改变包络与音区达到发展，不必一开始复刻复杂的波形序列系统。

### 17.2 Yuzo Koshiro：学习音乐类型的组织方式

古代祐三在 Red Bull Music Academy 的访谈中谈到俱乐部音乐的影响，以及用 FM 与有限的 PCM 资源组织声音；其中短采样承担鼓与短促音色，是值得关注的分工思路。[S14]

本文据此设计三项练习：

- 只用低音与鼓写出四小节，让节拍自身成立。
- 主旋律加入后，保留鼓与低音的核心律动，不让旋律把所有注意力夺走。
- 比较“用 FM 做这件声音”和“用短采样做这件声音”，选最适合当前资源与效果的一种。

这些访谈并不证明某个游戏某首曲目的每个通道都按本文方案分配。学的是创作策略，不把口述概括当成精确反汇编结论。

### 17.3 经典作品怎么听才有用

选择一个段落，逐次只听一件事：主题节奏、低音位置、内声移动、鼓的强弱、音头与尾巴、声部进入退出、循环入口。

每次写一句可执行记录，例如：“这里主旋律延长，鼓减少，因此我准备在自己的第 9 小节删掉镲。”比“这里有很棒的 SNES 感”更有帮助。

若用可分通道的播放器，先核对版本和输出路径。移植版、重制版与原主机版可能采用不同声音实现。

## 第 18 章：问题诊断与四周训练

### 18.1 按听到的症状改

| 症状 | 常见原因 | 先改什么 |
| --- | --- | --- |
| 全曲像廉价 MIDI | 音头、包络、声部表达缺少设计 | 先精修主旋律一条线的演奏 |
| SNES 版发糊 | 持续尾巴和 Echo 太多 | 缩短和声音长，减少送入回声的声部 |
| 采样像蜂鸣 | 稳态循环过短，缺少变化 | 保留音头，尝试更合适的持续段 |
| 循环素材咔嗒响 | 边界或 BRR 编码不连续 | 先查对齐，再听实际编码结果 |
| 乐器高处变尖 | 单采样移调范围过大 | 换音区、增加素材分区或改音色 |
| 同一和弦总不准 | 素材根音或音准不正确 | 逐素材校准，再改和声 |
| FM 总是硬、吵 | 调制太深，亮度持续不衰减 | 调制器更快衰减，降低反馈或调制强度 |
| FM 低音独奏酷、合奏虚 | 谐波抢占而基音不足 | 先恢复稳定载波与短促重心 |
| 电钢琴声音没了 | 运算器路由／载波被静音 | 看连接图，确认能到达输出的路径 |
| 鼓叠不起来 | DAC 单流或 Voice 预算限制 | 改节奏错位，或验证软件混音 |
| 只有第一轮正常 | 状态继承或回声初始化错误 | 明确入口状态并测多轮 |
| 声场宽但单声道缺音 | 相位反转或过度增强 | 先去掉反相，保住核心信息 |
| 每个段落一样满 | 缺少资源与密度规划 | 先空出一段，再设计回归 |
| 复古但不耐听 | 只模仿质感，没有明确主题和发展 | 独奏旋律加低音重写结构 |

### 18.2 修改顺序

先修场景与主题，再修和声与节奏，再修角色与密度，然后才是音色细节、空间、响度与格式。不要在旋律没有身份时，花一整晚研究镲的压缩率。

每次保存一个可比较版本，写清只改了什么、改善了什么、牺牲了什么。比较时匹配听感响度，不凭“更响所以更好”做选择。

### 18.3 四周训练

每天约 30—60 分钟，以完成短作品为目标。

| 阶段 | 任务 | 交付物 |
| --- | --- | --- |
| 第 1 周前半 | 单旋律写动机、问答、句尾变化 | 三个四小节主题 |
| 第 1 周后半 | 加低音与两内声，比较转位 | 一段八小节干声草稿 |
| 第 2 周前半 | 做四个短采样，校准根音与循环 | 一个小型可用音色库 |
| 第 2 周后半 | 完成 SNES 版并加入共享 Echo | 一段可循环的 16 小节 |
| 第 3 周前半 | 用一组调制器—载波完成 FM 实验 | 三种清楚可辨的音色变化 |
| 第 3 周后半 | 将同主题改成 MD 版 | 一段五 FM 加 DAC 的编曲 |
| 第 4 周前半 | 匹配响度比较两版，做减法 | 一份修改记录与修订工程 |
| 第 4 周后半 | 加游戏音效，测多轮与状态切换 | 一个目标场景中的最终版本 |

### 18.4 三项值得反复做的限制练习

1. **七声部预算**：保留一路给游戏音效，写完一首仍然完整的 SNES 风格短曲。
2. **五 FM 预算**：假定第六路给 DAC，不使用额外软件复音，写两段有对比的音乐。
3. **同主题三版本**：采样、FM、现代混合各做一版，说清主题身份与音色变化分别贡献了什么。

### 18.5 怎样算第一首完成

主题可辨认；场景合适；焦点清楚；至少一个段落有明确对比；资源预算说得清；五轮循环无突出问题；加入游戏音效后仍可用；工程能被下次继续修改。

完成后开始下一首。多次经历“初稿—诊断—修改—交付”，比永远等待一个完美音色更能建立判断。

## 附录 B：用 Python 制作一个可校准、可循环的原始素材

这个实验只生成一个简单的笛感持续音原料，用来理解谐波、根音与采样循环。它不是完整 SNES 仿真、BRR 编码器或音乐渲染器，也不声称能替代真实笛子采样。

用 Python 3 标准库即可运行。输出是单声道 16 位 PCM WAV；这里的“16 位”是文件精度，与它是否像 SNES 音色是两个概念。

```python
from pathlib import Path
import math
import struct
import wave

sample_rate = 17600
root_hz = 220.0  # A3, A4 = 440 Hz
seconds = 0.25
count = round(sample_rate * seconds)

values = []
for i in range(count):
    t = i / sample_rate
    phase = 2 * math.pi * root_hz * t
    # Fundamental plus two weaker harmonics.
    value = (
        math.sin(phase)
        + 0.20 * math.sin(2 * phase)
        + 0.08 * math.sin(3 * phase)
    )
    # A short attack only. The later section stays periodic.
    attack = min(1.0, t / 0.015)
    values.append(value * attack)

peak = max(abs(v) for v in values) or 1.0
pcm = [round(v / peak * 0.65 * 32767) for v in values]
output = Path("harbor_flute_A3.wav")
with wave.open(str(output), "wb") as wav:
    wav.setnchannels(1)
    wav.setsampwidth(2)
    wav.setframerate(sample_rate)
    wav.writeframes(struct.pack("<" + "h" * len(pcm), *pcm))

print(f"Wrote {output.resolve()}")
print("Root: A3 = 220 Hz")
print("Loop candidate: start=1600, end=3200, end is exclusive")
```

为什么这样选：

- 每个周期 `17600 / 220 = 80` 点，恰好是 16 的倍数。
- 候选循环 `[1600, 3200)` 跨 20 个完整周期，且两个位置都按 16 点对齐。
- 循环位于起音之后，避免重复播放音头。
- WAV 没有在此代码中写入循环元数据；必须在编辑器中手动设置。

导入后把根音映射为实际 A3，设置上述候选循环，再通过工具转换为 BRR。确认编辑器是否重采样过素材；重采样后旧索引不再直接有效。最终仍要听 BRR 编码与播放后的接缝，不用“原 WAV 数学上周期一致”代替验证。

三个小实验：

1. 把二次谐波系数从 0.20 改成 0.05，比较是否更柔和。
2. 保持素材不变，改成短拨奏包络，观察乐器身份如何改变。
3. 把同一素材弹低八度和高八度，记录音头、亮度与循环纹理变化。

若修改基频或采样率，重新计算周期与循环点，不要继续盲用 1600、3200。

## 附录 C：最值得留在创作台前的十二句话

1. 先让主题成立，再选择它的发声方式。
2. 16bit 是时代与声音环境的提示，不是一种固定音色。
3. 短采样的价值，在于保留身份并允许灵活演奏。
4. 循环点要满足格式，也要通过耳朵。
5. 八 Voice 是八路实际发声，不是八个无限复音乐器。
6. FM 音色的灵魂，往往在调制深度怎样变化。
7. 低音与鼓先站稳，其他声部才有发挥空间。
8. 共享空间用来连接声音，不用来淹没问题。
9. 高潮需要前面的克制。
10. 跨平台改编要改演奏与资源分配，不只换预设。
11. 好循环需要音乐衔接，也需要运行时验证。
12. 每一次修改，都要能说出它改善了哪种感受。
