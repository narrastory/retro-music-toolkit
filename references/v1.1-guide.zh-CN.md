# 1.1：从可编译的乐谱到可用耳朵判断的音乐

工具包版本 **1.1.0**，乐谱格式 **1.3**。本版的目标不是增加更多旋钮，而是让 AI 能写出**跨小节、有和声方向、有主题发展**的音乐，并且能自己发现最常见的和声错误。

旧谱（1.0–1.2）继续可用，无需迁移。新增字段全部可选。

1.1 补上了第一梯队里"听着像不像 8/16bit"和"AI 能不能自己判断结构"这两块缺口：硬件发声模式、单声部和弦轮换、SNES FIR 回声、循环收束诊断，以及钢琴卷帘与乐曲文字描述。

---

## 1. 跨小节延音：`hold`

旧版最限制写作的一条规则是「音符不能跨出 pattern」。为了写一个跨小节的长音，只能把 pattern 拉长，导致每个小节都变成独立 pattern。

现在：

```json
{ "id": "long", "kind": "note", "at": 3, "pitch": "C5", "duration": 2, "hold": true }
```

- `hold: true` 表示持续到**同轨下一个事件**（或 pattern 结尾）再松键，`duration` 仍用于表达意图和弯音曲线范围。
- 不写 `hold` 且越界时，报 `EVENT_BOUNDS`，`suggestion` 里直接给出可用的 `{ hold: true, maxDuration }`。
- 延音不占用额外的声部：它的尾音会在下一个音开始时被正常切断，这一点在诊断里标记为 `RELEASE_CUT`（info），而不是声部冲突。

配套的 **clip 裁剪**让同一个 pattern 可以只播前几拍：

```json
{ "id": "lead-b", "pattern": "theme", "at": 16, "lengthBeats": 6 }
```

`lengthBeats` 超过 `pattern.lengthBeats × repeats` 会报 `CLIP_BOUNDS`。

**这两条合起来，抹掉了示例谱里大量的 pattern 复制。** 旧示例的鼓轨有 16 个 pattern、实际只有 2 种内容——那是旧模型逼出来的写法。

## 2. 节奏与人性化

### swing

```json
{ "id": "lead", "swing": 0.6, "swingUnit": 0.5 }
```

`swing: 1` 把每一对八分音符中的第二个推到 2/3 拍位置，重拍不动；`swingUnit: 0.25` 则作用于十六分。位移在编译期完成，所以：

- `compile` 输出的 tick 已经包含摆动；
- 循环边界、声部冲突、诊断都基于实际发声时间；
- 不需要在播放器里做时间拉伸。

```
swing 0   : 0, 0.5, 1, 1.5
swing 0.5 : 0, 0.583, 1, 1.583
swing 1   : 0, 0.667, 1, 1.667
```

### humanize

```json
"humanize": { "timingBeats": 0.01, "velocity": 0.05 }
```

抖动由 `seed + 轨道 + clip + 重复序号 + 事件 ID` 派生，同一份工程每次导出完全相同的结果——可复现性不因人性化而丢失。范围建议很小（时序 ≤ 0.02 拍）；超出会让节奏听起来像演奏失误。

### quantize（patch 操作）

```json
{ "op": "quantize", "trackId": "lead", "pattern": "A", "grid": 0.25, "strength": 0.6 }
```

`strength: 0` 完全吸附，`1` 完全不量化；`includeHits: false` 可只处理音符。量化不会把事件推到 pattern 之外。

## 3. 和声：从注释变成可用的音乐信息

旧版的 `harmony` 只是校验过边界的字符串。现在它有三个用途。

### 3.1 key 与和弦解析

```json
"key": { "tonic": "A", "mode": "minor" },
"harmony": [
  { "at": 0, "chord": "Am" },
  { "at": 8, "chord": "F", "lengthBeats": 4 },
  { "at": 12, "chord": "G" }
]
```

支持 `C`、`Am`、`Fmaj7`、`G7`、`Dm7`、`Bdim`、`Gsus4`、`Cadd9`、`Csus2`、`C/E`（斜杠低音）等。无法解析时报 `CHORD_PARSE` 并列出支持列表，而不是静默忽略。

### 3.2 和声诊断

`diagnose` 新增以下规则（仅在存在相应数据时运行）：

| 规则 | 触发条件 | 默认级别 |
| --- | --- | --- |
| `HARMONY_NON_CHORD_TONE` | 强拍、时长 ≥ 半拍、非和弦音，且前后没有级进解决 | warning |
| `BASS_NON_CHORD_TONE` | 低音与当前和弦音集冲突 | warning |
| `BASS_SLASH_CHORD` | 斜杠和弦但低音弹了根音 | info |
| `PARALLEL_FIFTHS` | 旋律与低音同向进行且保持纯五度 | warning |
| `PARALLEL_OCTAVES` | 同上，纯八度 | info |
| `UNRESOLVED_LEAP` | ≥ 7 度跳进且继续同向 / 继续扩大 | info |
| `OUT_OF_KEY` | 调外音；占比 > 25% 升级为 warning | info/warning |
| `MINOR_SECOND_CLASH` | 两条轨反复出现半音碰撞（≥ 3 次） | info |
| `HARMONY_GAP` | 和弦标记没有覆盖整首曲子 | info |
| `HARMONY_ZERO_LENGTH` | 和弦标记长度为 0 | warning |

设计原则：**只在强拍、只对足够长的音、并且允许经过音/辅助音的级进解决**。这样 chiptune 里大量合法的半音经过音不会被误报成错误。

```bash
node dist/cli.js diagnose song.json
```

### 3.3 直接生成伴奏：`harmonize`

```bash
node dist/cli.js harmonize song.json --config harm.json --out with-harmony.json
```

```json
{
  "style": "drop2",
  "anchorMidi": 60,
  "output": { "kind": "new-track", "trackId": "harmony", "instrument": "fm-epiano", "maxVoices": 4 }
}
```

- `style`：`close`（收拢）、`open`（开放）、`drop2`、`root-position`。
- 输入来自 `harmony` 标记；没有标记会明确报 `NO_HARMONY`，不会凭空生成。
- 只做音区排列，不做跨和弦的声部进行优化——报告里会写清这一点。

### 3.4 从已有和弦音生成琶音：`arpeggiate`

```bash
node dist/cli.js arpeggiate song.json --config arp.json --out with-arp.json
```

```json
{
  "trackId": "arp",
  "clipId": "arp-section-1",
  "newPattern": "arp-updown",
  "pattern": "updown",
  "stepBeats": 0.25,
  "octaves": 2,
  "accent": 0.1
}
```

`pattern` 支持 `up` / `down` / `updown` / `downup` / `random`（`random` 由 seed 决定，可复现）。

## 4. 主题发展：`motif`

这是本版对「16 小节不重复」帮助最大的一条。它把常见的作曲手法变成可组合的算子，只作用于选中的拍区间，原 pattern 保持不变。

```bash
node dist/cli.js motif song.json --config motif.json --out developed.json
```

```json
{
  "trackId": "lead",
  "clipId": "lead-section-2",
  "newPattern": "A-developed",
  "fromBeat": 0,
  "toBeat": 4,
  "operators": [
    { "op": "transpose", "degrees": 2 },
    { "op": "retrograde" },
    { "op": "velocityShape", "amount": 0.5 }
  ],
  "replaceClip": true
}
```

支持的算子：

| op | 说明 | 关键参数 |
| --- | --- | --- |
| `transpose` | 半音移调或**音阶级移调** | `semitones` 或 `degrees`（需要 `key`） |
| `invert` | 倒影；轴默认是选区第一个音 | `axisMidi` |
| `retrograde` | 逆行（保持音高、反转时间） | — |
| `scaleDuration` | 时值增减值 | `factor` |
| `scaleGate` | 只改断连 | `factor` |
| `velocityShape` | 拱形或谷形力度曲线 | `amount` |
| `ornament` | 上/下/回音装饰 | `kind`、`lengthBeats` |

报告会返回：`operators`、`selectedEventIds`、`resultPitches`、`preservedEventCount`、`diagnostics`。移调越界、`invert` 轴导致 MIDI 超界、选区内没有音符，都会带明确错误码失败，不会产生半成品。

「保留原句 + 只改句尾」仍然用 `vary`；「整句做机械变形」用 `motif`。两者都会写到新 pattern，靠 `clone-pattern-for-clip` 保证原段落不受影响。

## 5. 鼓：独立 one-shot + 采样鼓组

### 5.1 声部语义修正

1.0 之前，鼓轨也参与声部抢占：`maxVoices: 1` 时同一拍的底鼓与踩镲会互相抢断，最坏情况下其中一个音的时长为 0 被直接跳过。现在**鼓轨完全不参与声部计数**，每次击打都是独立 one-shot，是否重叠由混音与削波检查负责。

> 这是本版最重要的 bug 修复。旧示例的鼓全部把踩镲写在反拍，是为了绕开这个问题。

### 5.2 八种鼓件

`kick`、`snare`、`hat`、`openhat`、`tom`、`crash`、`rim`、`clap`，可用 `detuneCents` 逐次微调（对 tom / kick 尤其有用）。

### 5.3 采样鼓组

```json
{
  "instrument": {
    "id": "my-kit",
    "engine": "drums",
    "role": "drums",
    "range": [0, 127],
    "attack": 0,
    "release": 0,
    "description": "Original sampled kit",
    "drumKit": {
      "slots": [
        { "sound": "kick", "assetId": "kick-1", "gainDb": -2 },
        { "sound": "snare", "assetId": "snare-1", "tuningCents": 20, "startFrame": 120 }
      ]
    }
  },
  "assets": [
    { "id": "kick-1", "file": "kick.wav", "provenance": "Original recording" },
    { "id": "snare-1", "file": "snare.wav", "provenance": "Original recording" }
  ]
}
```

未提供采样的鼓件会回退到内置合成鼓，并在诊断里给 `DRUM_SLOT_MISSING`（warning）——不会静默无声。

## 6. 导出：真峰值、响度、抖动与限幅

报告新增三个测量：

| 字段 | 含义 |
| --- | --- |
| `truePeakDbfs` | 4× 多相 sinc 过采样的真峰值（BS.1770 Annex 2 思路） |
| `loudnessLufs` | BS.1770-4 积分响度（400 ms 块、75% 重叠、-70 LUFS 绝对门限、-10 LU 相对门限） |
| `limiter` | 限幅触发器数量与最大衰减 |

判断「会不会在播放器里爆音」请用 `truePeakDbfs`。采样峰值 -1 dBFS 的曲子，真峰值完全可能超过 0。

```bash
# 抖动（PCM16 量化前的确定性 TPDF）
node dist/cli.js render song.json --out final.wav --dither

# 固定峰值上限的软限幅
node dist/cli.js render song.json --out final.wav --limiter -1

# 循环边界等功率交叉淡化（拍数）
node dist/cli.js render song.json --out loop.wav --loop-crossfade 0.01
```

三者都默认关闭。限幅器是导出安全网，不是母带压缩；交叉淡化只隐藏接缝，不修复音乐上的收束。

### A/B 对比导出

```bash
node dist/cli.js compare v1.wav v2.wav --out ab.wav --match-rms -24
```

两版按 RMS 等响导出，用 0.5 秒静音拼接成一个文件，报告分别给出真峰值、LUFS 与实际施加的增益。

## 7. 采样导入：读取 `smpl` 块

`decodeWav` 现在接受 PCM16 / PCM24 / PCM32 / float32，容忍 `LIST`、`bext` 等附加块与不准确的 RIFF 长度，并读取 `smpl` 块里的根音与循环点：

- `import-instrument` 会自动把 `smpl` 的 unity note 与循环区间填进 zone；
- 循环点仍建议人工确认（真实素材的循环点常常需要微调）；
- zone 新增 `loopCrossfadeFrames`，用于在循环点做短交叉淡化。

`node dist/cli.js analyze sample.wav` 会报告输入文件自带的循环点。

## 8. CLI 与 Agent 易用性

```bash
# 从 stdin 读、往 stdout 写（不再强制落盘）
cat song.json | node dist/cli.js validate -
node dist/cli.js patch song.json --patch p.json --out - | jq .

# 按小节渲染，而不是自己算拍
node dist/cli.js render song.json --bars 9-16 --mode one-shot --out phrase.wav

# 给 Agent 的紧凑 JSON
node dist/cli.js diagnose song.json --compact

# 最小可用乐谱（40 行左右，取代 87 KB 的示例）
node dist/cli.js example --out minimal.json
```

- `--solo lead, bass` 现在会正确 trim。
- 退出码：`0` 成功，`1` 工具/IO 错误，`2` 乐谱校验失败。
- 所有工具错误都是 `{ error, code, details? }`，`code` 可被程序分支判断。
- `patch` 返回逐项变更日志（见乐谱格式文档第 5 节）。

## 8.5 硬件发声模式（1.1 新增）

`"authenticity": "hardware"` 是全局开关，默认 `"modern"`。

| 项 | modern | hardware |
| --- | --- | --- |
| 轨道安全低通 | 1200–13200 Hz 平滑过渡 | **完全移除**（2A03 脉冲无滤波） |
| 脉冲占空比 | 连续值 | 吸附到 12.5 / 25 / 50 % 三档 |
| 音量 | 连续 dB | 16 级线性量化 |
| SNES 回声 | 仅一条共享延迟 | 可启用八抽头 FIR 回声 |

实测同一段旋律，hardware 模式的高频能量比（一阶差分/总能量）从 0.256 升到 0.368——听感上是"更扎、更硬"。这仍是近似，不是仿真。

```json
{
  "authenticity": "hardware",
  "mixer": {
    "echo": { "enabled": true, "delayBeats": 0.5, "feedback": 0.5, "taps": [0.6, -0.3, 0.2, -0.1], "returnDb": -14 }
  }
}
```

`mixer.echo.taps` 最多 8 个抽头，第 n 个抽头的延迟为 `delayBeats × (n+1)`；反馈取自抽头求和**之后、返回增益之前**，因此 `returnDb` 不会改变反馈量。回声湿声跟随轨道 `send`。

## 8.6 单声部和弦轮换（1.1 新增）

真实的一路脉冲声道无法同时发三个音。芯片音乐的做法是让音高快速在三个音之间轮换，靠听觉融合成和弦。这就是 `arpeggio`：

```json
{
  "id": "lead",
  "instrument": "pulse-lead-soft",
  "maxVoices": 1,
  "arpeggio": { "rate": 16, "gate": 1, "order": "up" }
}
```

```json
"events": [
  { "id": "c", "kind": "note", "at": 0, "pitch": "C5", "duration": 2 },
  { "id": "e", "kind": "note", "at": 0, "pitch": "E5", "duration": 2 },
  { "id": "g", "kind": "note", "at": 0, "pitch": "G5", "duration": 2 }
]
```

- 同一拍上起始的音符被合并成**一个声部**，在编译期展开为 `rate` 步/拍的音高序列；`rate: 16` 在 120 BPM 下是每 60 tick 一步。
- `order`：`up` / `down` / `updown` / `as-written`。
- `gate` 控制每一步的保持比例；1 表示包络连续（最像芯片）。
- 合并发生在声部分配**之前**，所以结果只占一个声部，不会再触发 `VOICE_STEAL`。

**不要用提高 `maxVoices` 来写芯片和弦**——那会得到三个同时发声的合成器，而不是一路声道的轮换。

## 8.7 循环收束诊断（1.1 新增）

`diagnose` 在 `export.mode: "loop"` 且存在 `harmony` 标记时新增两条规则：

| 规则 | 判据 |
| --- | --- |
| `LOOP_HARMONY_RETURN` | 末和弦与首和弦既不相同、也不构成纯四/纯五（属→主）关系 |
| `LOOP_MELODY_UNRESOLVED` | 末小节前就静音，或长音跨过循环点 |

它们回答的是信号检查回答不了的问题：**这个循环是"接回去了"还是"重新开始了"**。

## 8.8 看结构：`report` / `describe` / `roll`（1.1 新增）

```bash
# 钢琴卷帘 + 结构 + 信号 + 诊断，单个自包含 HTML
node dist/cli.js report song.json --wav song.wav --out report.html

# 纯文本描述，适合直接放进模型上下文
node dist/cli.js describe song.json

# 只有钢琴卷帘 SVG
node dist/cli.js roll song.json --out roll.svg
```

`describe` 输出的是**可推理的音乐叙述**，不是指标堆：

```
- lead (pulse-lead-soft, melody): 83 notes, 5.2/bar, range B4–C6,
  peak C6 at beat 33.00, 49% stepwise motion
Sections:
  A1: bar 1, 5.88 events/beat, median F4 — opening
  A2: bar 5, 5.88 events/beat, median F4 — similar to previous
  B: bar 9, 5.56 events/beat, median F4 — similar to previous
```

钢琴卷帘把音符按轨道着色、标出小节线、段落带与和弦符号；鼓轨用独立行显示八种鼓件。SVG 是纯文本，模型可以直接读事件位置，人类可以直接打开。

## 9. 破坏性变更

| 变更 | 影响 | 迁移 |
| --- | --- | --- |
| `TrackSchema.voicePolicy` 默认值 `error` → `cut` | 之前靠默认值报错发现的尾音重叠，现在只给 info | 需要严格模式就显式写 `"error"` |
| 鼓轨不再参与声部检查 | `maxVoices` 对鼓无效 | 删除鼓轨上多余的 `maxVoices: 2` |
| `patchScore()` 仍返回乐谱，但新增 `patchScoreWithReport()` | 旧代码不受影响 | 需要变更日志时改用新函数 |
| `hitDuration` 改为接受八种鼓件 | 内部 API | 传入 `sound` 字符串即可 |
| `schemaVersion` 写 `"1.3"` | 旧版本工具无法读取新谱 | 需要兼容旧工具时保持 `"1.0"` |
| `loudnessLufs` 门限改为能量域平均 | 稀疏、长尾曲目的读数会变化（此前偏高最多 11 LU） | 无；旧读数本身是错的 |

`ScoreSchema` 依旧是严格对象；拼错的字段仍然直接报错，这是有意的。
