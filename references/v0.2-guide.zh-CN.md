# 第二版：试听、编辑、诊断和回归验证

工具包版本 **0.2.0**，乐谱格式继续使用 **schemaVersion: "1.0"**。现有乐谱和第一版命令可以继续使用。

## 1. 音色试听与信号校准

```bash
cd scripts/runtime
npm ci
npm run build
node dist/cli.js audition --out output/auditions
```

生成每个音色的 WAV、标准参考谱、测量报告，以及 `index.html`、`manifest.json`、`listening-review.json`。也可以只测试一个音色：

```bash
node dist/cli.js audition --instrument fm-epiano --out output/epiano
```

11 个预设各使用固定参考事件，包含推荐范围内低/中/高音、短音/长音、弱力度 .4 / 强力度 .8；鼓按 kick、snare、hat 分组。不同音色的可用音域不同，因此这是“各自可用音区的标准测试”，并非完全相同绝对音高的盲测。

参考音频全文件 RMS 默认匹配至 -24 dBFS；试听库默认最大提升 24 dB，样本峰值上限 -3 dBFS。长短音之间包含有意的空白，因此 RMS 包含休止。报告给出目标、实际增益、编码前后测量和受限原因。匹配在浮点 PCM 阶段执行，最后才编码 WAV。

RMS 匹配不是感知响度匹配，不包含 LUFS、true peak、压缩或主观音质评审。试听页和 review 文件始终保持“未听审”状态，直到真实听音者填写。当前交付不声称已完成主观音色校准。

对任意曲目生成音量比较副本：

```bash
node dist/cli.js render examples/neon-overpass.json --match-rms -24 --out output/compare.wav
```

普通 render --match-rms 的默认最大提升为 18 dB；audition 参考库为覆盖较轻的音色，默认允许 24 dB。两者都受 -3 dBFS 样本峰值限制。默认 render 不改变谱子电平。比较副本不会将匹配增益写回乐谱；它属于导出选项。API 使用 `normalization: { targetRmsDbfs: -24, peakCeilingDbfs: -3, maxBoostDb: 18 }`。

## 2. 局部编辑操作

所有操作放在 patch 的 operations 数组内按顺序执行；完整事务结束后统一编译。任一步或最终校验失败，原谱子保持不变，CLI 不生成新谱子。

| 操作 | 字段 | 语义 |
| --- | --- | --- |
| insert-events | trackId、pattern、events | 插入 note/hit，使用完整事件 Schema；ID 不可重复 |
| delete-events | trackId、pattern、eventIds | 所有被选 ID 必须存在，防止误以为删除成功 |
| clone-pattern-for-clip | trackId、clipId、newPattern | 复制 pattern、分配新事件 ID，并仅重定向指定 clip |
| transpose-phrase | trackId、pattern、fromBeat、toBeat、semitones | 按起音位于 [fromBeat,toBeat) 选择 note，保持时间与门长 |
| scale-rhythm | trackId、pattern、factor | 缩放整个 pattern 的时间、音长与颤音延迟，所有引用均受影响 |
| duplicate-section | sectionId、newSectionId、at、expandSong | 复制段落注释、和声标记和完整包含的 clips；默认不扩展工程 |

复制段落时源 clip 不可跨段落边界；目标时间区间必须没有其他 section、clip 或 harmony 标记。pattern 被复用，复制段落之后若需要独立修改某条 clip，再使用 clone-pattern-for-clip。

节奏缩放之后的时间仍必须可用 PPQ=960 表示，clip 不能越出工程边界；如需先扩展工程，请直接修改 lengthBeats 后校验，或在适用时使用 duplicate-section 的 expandSong。

音高移调直接写回源 note，因此结果必须在 C0–B8 范围；clip.transpose 的最终 MIDI 范围仍是 0–127。被选 note 跨出选区时，按起音选择；此操作不裁切音长。

### 修改某一次主题重现

```json
{
  "operations": [
    {
      "op": "clone-pattern-for-clip",
      "trackId": "lead",
      "clipId": "lead-clip-4",
      "newPattern": "a2-answer"
    },
    {
      "op": "transpose-phrase",
      "trackId": "lead",
      "pattern": "a2-answer",
      "fromBeat": 2,
      "toBeat": 4,
      "semitones": -2
    }
  ]
}
```

完整可运行示例在 `examples/v2-variation.patch.json`。移调只是机械变换，仍应检查和声与乐句去向。

### 修复：局部修改不会注入默认值

从 v0.2 起，`set-note` 只传 pitch 时保留原 gate 和 velocity。嵌套 set 递归合并，例如 `set-song: { mixer: { feedback: 0.1 } }` 会保留原 masterDb、delayBeats 和 returnDb。未知字段继续报错；不支持用 null 删除可选参数，删除/重建事件或直接编辑 JSON 后校验即可。

## 3. 可定位的编曲诊断

```bash
node dist/cli.js diagnose examples/pixel-trail.json --out output/findings.json
node dist/cli.js diagnose examples/pixel-trail.json --rules examples/diagnostic-rules.json
```

输出包括规则名、声部、起止拍、1 起点小节号、源音符 ID、clip ID、证据与可尝试的修改。不会生成“音乐质量总分”，不会自动修改谱子，也不会因为建议未采纳而阻止导出。

| 规则 | 观察内容 |
| --- | --- |
| MELODY_NO_BREATH | 至少 8 拍的主旋律段落缺少足够松键空白 |
| REGISTER_CROWDING | 主旋律和伴奏同时密集发声且中位音高接近 |
| PERCUSSION_DENSITY | 镲音事件密度达到设定阈值 |
| SLOW_ATTACK_NOTES | 多个音符门长短于该预设起音所需时间 |
| SECTION_SIMILARITY | 相邻段落密度、活跃轨道和中位音区相近 |
| MOTIF_VARIETY | 四拍片段没有发现精确、移调不变的动机重复 |

所有判断都是启发式。连奏、持续紧张感、重复段落或复杂变奏可能完全符合创作意图。特别是 MOTIF_VARIETY 无法识别所有节奏变形或自由乐句，默认仅提供 info。

配置示例：

```json
{
  "disabledRules": ["MOTIF_VARIETY"],
  "thresholds": {
    "windowBeats": 4,
    "crowdingSemitones": 5,
    "crowdingNotesPerBeat": 1,
    "hatHitsPerBeat": 3
  }
}
```

## 4. 干声 / 效果返回与循环检查

```bash
node dist/cli.js render examples/lantern-harbor.json --effects dry --out output/dry.wav
node dist/cli.js render examples/lantern-harbor.json --effects wet --out output/wet.wav
node dist/cli.js render examples/lantern-harbor.json --loop-diagnostics --out output/loop.wav
```

mix 为默认，dry 保留轨道滤波和声像，wet 仅输出共享延迟返回。没有 send 的曲目 wet 静音属于正常行为。

`--loop-diagnostics` 要求 loop 模式，在同一浏览器中串行渲染完整混音、干声和效果返回，分别报告绝对周期差、信号 RMS、相对周期差和边界指标。额外渲染会增加时间；每一遍有独立 120 秒保护。它不自动断言差异来源于相位、音序或效果器，必须结合独奏和实际试听定位。

当主输出使用 --seam 或 --match-rms 时，详细循环诊断仍基于**未匹配音量的完整循环**，避免比较对象混淆。

## 5. API

```ts
import { diagnoseScore, patchScore, renderScore, createAuditionScore, exportAuditions } from './dist/index.js';

const findings = diagnoseScore(score, { disabledRules: ['MOTIF_VARIETY'] });
const next = patchScore(score, { operations: [
  { op: 'set-track', trackId: 'arp', set: { controls: { brightness: 0.35 } } }
] });
const audio = await renderScore(next, { loopDiagnostics: true });
const reference = createAuditionScore('fm-epiano');
await exportAuditions('output/auditions', { instrumentIds: ['fm-epiano'] });
```

所有这些 API 可以继续包装为宿主工具；当前版本未附带 MCP server，也未新增硬件仿真或 MIDI 功能。
