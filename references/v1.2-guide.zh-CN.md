# 1.2：轻量采样音色包与立体声混响

这一版保留原有 11 个程序音色，新增四件基于 VCSL CC0 录音的入门乐器：

| ID | 乐器 | 根音采样数 | 推荐 MIDI 音区 |
| --- | --- | --- | --- |
| `starter-recorder` | 竖笛，可循环延音 | 2 | 60–96 |
| `starter-piano` | 钢琴，单次衰减 | 5 | 48–96 |
| `starter-kalimba` | 卡林巴，单次衰减 | 3 | 48–88 |
| `starter-glock` | 钟琴，单次衰减 | 2 | 72–108 |

整个音色包约 1.9 MB，12 个 WAV，单声道 PCM16 / 32 kHz。它是面向复古配乐的轻量选择，不是多力度、多奏法管弦音源。素材根音按本工具的 C4=MIDI 60 约定校准，并记录微调值与处理过程。

## 使用内置采样包

在 `scripts/runtime` 目录安装并构建后：

```bash
node dist/cli.js instrument-packs
node dist/cli.js example --out output/song.json
node dist/cli.js import-pack output/song.json --instrument starter-recorder,starter-piano --out output/with-samples.json
node dist/cli.js instruments --score output/with-samples.json
```

导入将选中的乐器及其 WAV 内嵌到新乐谱中，不会自动改变现有轨道。将轨道的 `instrument` 改成对应 ID，或通过 `patch` 的 `set-track` 修改，再进行渲染。省略 `--instrument` 会导入整套四件乐器。

现有 CLI 的 `audition` 已支持内嵌乐器：

```bash
node dist/cli.js audition --score output/with-samples.json --instrument starter-recorder --out output/recorder-audition
node dist/cli.js render output/with-samples.json --out output/song.wav
```

导出后的乐谱不依赖原音色包的位置，不联网也可播放。文件较大时可只导入真正用到的乐器。现有单资产及工程总采样帧上限继续生效。

## 添加自己的本地音色包

入门包位于 `scripts/runtime/instruments/starter/`，包含：

- `pack.json`：音色集合清单、音区、包络、循环点、资产路径和哈希。
- `samples/`：对应 WAV。
- `LICENSE.txt`：完整上游 CC0 许可。
- `SOURCES.json`：上游固定版本、原文件及处理后哈希、校准信息。

自己的包可放在任意本地目录，使用 `--definition` 指向其清单：

```bash
node dist/cli.js instrument-packs --definition D:/Audio/my-pack/pack.json
node dist/cli.js import-pack song.json --definition D:/Audio/my-pack/pack.json --out portable.json
```

清单顶层为 `id`、`name`、`version`、`license`、`source`、`instruments`。每项 `instruments` 使用与 `import-instrument` 一致的 `instrument` 与 `assets` 结构，额外要求每个资产声明 `sha256`。
采样路径相对清单目录，必须留在该目录内；越界路径、越界符号链接、内容哈希不匹配和重复 ID 会拒绝导入。导入前检查常规文件类型与大小，单文件最多 6 MB、已有内嵌资产加本次导入最多 24 MB，原有采样帧上限也继续生效。失败不会修改原乐谱或生成半成品输出。
JS API 为 `importInstrumentCollection(score, manifest, baseDirectory, instrumentIds?)`。

完整入门包可直接作为清单格式参考。SF2、SFZ 和 VST 不在本轮直接加载范围内。

## 混响

乐谱继续使用 `schemaVersion: "1.3"`。在 `mixer` 中添加：

```json
{
  "reverb": {
    "enabled": true,
    "decaySeconds": 1.2,
    "preDelaySeconds": 0.025,
    "damping": 0.6,
    "returnDb": -10
  }
}
```

这是 `mixer` 内的片段，不是完整乐谱。然后在需要空间的轨道上添加 `"reverbSend": 0.25`。
原有 `send` 仍控制节拍延迟和 FIR 回声；`reverbSend` 单独控制卷积混响，默认 0。
`damping` 越大，混响越暗。混响返回电平同时适用于 `mix` 与 `wet` 试听。

参数范围：衰减 0.1–4 秒、预延迟 0–0.2 秒、阻尼与发送量 0–1、返回增益 −60–0 dB。
本轮发送量为静态参数，不提供 `reverbSend` 自动化通道。

脉冲响应由乐谱 seed 生成，左右声道不同，具有预延迟与衰减。引擎不调用运行期 `Math.random()`，也不需要下载房间脉冲文件。浏览器 DSP 仍不承诺跨平台逐样本一致。

建议先给旋律 0.15–0.3、和声 0.1–0.2，低音和底鼓保持 0，再结合曲目试听。新字段缺省时不创建混响路径；老乐谱继续使用原有声音。
`--effects dry` 会绕过混响，`--effects wet` 可单独检查效果尾音。one-shot 导出需留足 `tailSeconds`；loop 导出仍需检查音乐收束和边界，不以加大混响掩盖问题。

## 听到并复现差别

[在线音色实验室](https://narrastory.github.io/retro-music-toolkit/sound-lab.html) 使用《红叶邮便》第 9–16 小节，比较：

1. 原有程序音色、无效果。
2. 竖笛 / 卡林巴 / 钢琴采样、无效果。
3. 相同采样版本，加独立轨道发送的立体声混响。

三个版本保持音符、时间、力度与轨道增益一致，试听副本以全文件 RMS −24 dBFS 为目标、限制峰值，不是 LUFS 或感知响度匹配。具体增益见各渲染报告；这不是主观听审结论。

```powershell
$env:RETRO_CHROMIUM_EXECUTABLE = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
node scripts/create-sound-lab.mjs
```

Chrome 路径可替换，已安装 Playwright Chromium 时可省略环境变量。MP3 编码需要 ffmpeg。

可选的 `node scripts/prepare-starter.mjs` 用于从固定 VCSL 版本重建素材，正常使用无需执行。`--list` 输出原素材路径及缓存存放位置，可在下载受限时手动填充 `.cache/vcsl/` 后重新执行。准备脚本需要 ffmpeg；运行时没有新增 npm 依赖。
